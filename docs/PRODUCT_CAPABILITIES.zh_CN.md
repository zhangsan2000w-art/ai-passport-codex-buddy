# AI Passport 硬件能力与可开发方向

## 先说明范围

这份说明只回答两个问题：**拿到这块硬件，它本身能做什么；基于它可以开发什么。**
它不把 Codex Buddy 当前已经写好的功能算作硬件能力，也不把设想写成已经实现。

能力判断分为三档：

- **产品规格确认**：来自产品资料和已提供的硬件参数。
- **源码接口确认**：公开源码中已经有对应 BSP 驱动或 ESP-IDF 配置。
- **待硬件确认**：规格中存在，但公开 BSP 没有接口，或还需要确认具体器件和电路。

## 1. 硬件规格

| 类别 | 规格 |
| --- | --- |
| 屏幕 | 240 × 320 TFT |
| 输入 | 3 枚功能键 |
| 音频 | 内置扬声器 |
| 主控 | ESP32-C3FH8X |
| 电池 | 500 mAh |
| 无线 | Wi-Fi / BLE |
| 近场通信 | NFC |
| 接口 | USB Type-C |
| 尺寸 | 60 × 95 × 8.5 mm |
| 重量 | 50 g |

## 2. 这块硬件具体有什么能力

| 硬件 | 能力 | 开源支持状态 | 重要边界 |
| --- | --- | --- | --- |
| 240 × 320 TFT | 显示中文、图标、二维码、列表、简单动画、像素宠物和轻量游戏 | 显示与 LVGL BSP 已提供 | 没有发现触摸驱动，交互主要依靠三枚按键 |
| 3 枚功能键 | 菜单导航、确认/取消、短按、双击、长按、唤醒 | BSP 已提供；三键通过同一个 ADC 引脚区分 | 不能提供键盘级的大量文字输入 |
| ESP32-C3FH8X | 运行嵌入式界面、状态机、传感器逻辑、网络协议和轻量计算 | ESP-IDF 目标与板级配置已提供 | 无 PSRAM，不能在本机运行大语言模型，图片、字体和动画需控制内存 |
| Wi-Fi | 连接局域网或互联网、访问 API、接收消息、Web 配网和 OTA | 芯片具备；可使用 ESP-IDF 网络能力 | 持续联网会明显增加功耗，具体云服务需要单独开发 |
| BLE | 与手机或电脑近距离连接、传输小数据、遥控和配网 | 芯片与 ESP-IDF 支持 | 适合状态和指令，不适合持续传输大文件或高码率音频 |
| NFC | 碰一碰识别、打开链接、交换少量身份或场景信息 | 产品规格确认；公开 BSP 暂未发现 NFC API | 必须先确认 NFC 芯片、天线、读写模式和驱动，不能仅凭“有 NFC”断言可读写任意卡片 |
| 内置扬声器 | 提示音、闹钟、短语音播报、简单音效 | ES8311 音频与 I2S 播放接口已提供 | 长时间播放耗电；音量和音质受小体积扬声器限制 |
| 音频输入链路 | 源码中存在 ES8311 全双工 I2S 与录音路径 | 源码接口确认 | 已提供的产品参数只明确扬声器，真机是否安装并开放麦克风仍需确认 |
| 500 mAh 电池 | 便携运行、显示电量和电压、做低电量提醒 | CW2017 电量计 BSP 已提供 | 续航取决于屏幕亮度、联网、BLE 和音频使用；500 mAh 本身不能直接换算固定续航 |
| 休眠能力 | 自动息屏、轻度休眠、按键恢复；更深休眠可进一步省电 | ESP32-C3 具备低功耗模式 | 深度休眠通常会中断 BLE/Wi-Fi；三键共用 ADC，深睡唤醒策略需在真机验证 |
| USB Type-C | 供电、充电、刷写固件和串口/JTAG 调试 | 当前配置确认 USB Serial/JTAG | 目前不能据此宣称支持 U 盘、视频输出或任意 USB 外设模式 |
| 机身 | 50 g、卡片大小，可随身携带或做桌面小终端 | 产品规格确认 | 小体积限制了散热、电池、扬声器和天线空间 |

## 3. 基于这块硬件可以开发什么

### A. 屏幕信息工具

- 时钟、倒计时、番茄钟、喝水和久坐提醒。
- 日历、待办、天气、行情、物流、公交或服务器状态卡片。
- 二维码名片、Wi-Fi 二维码、活动签到码和临时凭证展示。
- 桌面通知器、任务完成灯牌、构建/测试结果和智能家居状态面板。

### B. 随身数字宠物与轻量游戏

- 像素宠物、表情动画、成长值、任务奖励和每日互动。
- 依靠三键操作的答题、计时、反应力、迷宫、电子骰子等小游戏。
- 徽章、连续打卡、专注积分和学习进度展示。

### C. BLE / Wi-Fi 连接设备

- 手机或电脑的提醒副屏、演示翻页器、音乐控制器和快捷按钮。
- 局域网设备遥控器、Home Assistant 面板、Webhook 按钮。
- 连接云端 API 的信息终端，或由电脑/手机负责计算、卡片负责显示和交互。
- 局域网配置页、固件 OTA、个性化主题和内容同步。

### D. NFC 玩法

- 碰一碰打开个人主页、作品集、联系方式或设备配网页面。
- 场景切换、身份徽章、展会互动、签到和收藏系统。
- 与屏幕联动：NFC 触发后显示对应角色、卡片、任务或奖励。

这些方向都要等 NFC 器件和驱动确认后再定方案；门禁卡复制、支付卡模拟等能力不能预设。

### E. 音频玩法

- 提示音、整点报时、闹钟、成功/失败音效和短语音播报。
- 如果真机确认有麦克风，可做按键录音、语音留言、云端语音识别入口。
- 与网络服务配合，可做简短语音问答；语音识别和大模型推理应放在电脑或云端。

### F. 学习与开发工具

- ESP32-C3、LVGL、BLE、Wi-Fi、NFC、低功耗和嵌入式 UI 的学习板。
- 传感器数据显示终端；是否能外接传感器取决于机身是否引出可用 GPIO/I²C 接口。
- 固件实验、交互原型、展会 Demo、个人作品集硬件载体。

## 4. 最重要的能力边界

- 它是一个**联网微控制器小终端**，不是能独立运行 Codex 或大模型的掌上电脑。
- 当前证据不支持触摸屏、本地大模型、摄像头、任意 USB 外设模式等说法。
- “硬件有 Wi-Fi、BLE、NFC”只代表存在开发空间，不代表对应产品功能已经写好。
- NFC 和麦克风需要实物或原理图确认；公开 BSP 的缺失不等于硬件一定没有，也不能当作已经可用。
- 真正续航需要用目标固件在不同亮度、联网和音频场景下实测。
